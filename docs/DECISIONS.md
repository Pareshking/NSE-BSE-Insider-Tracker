## 2026-10-09 Point-in-time market cap and adjustment factors (owner directive: inspect `mcap`, cover BSE)
- VERIFIED: the NSE PR zip's `mcap` file exists for 2025-01-15 and 2026-10-08, same columns: trade date, symbol, series, name, category (Listed/Permitted), face value, **issue size** (shares in issue that day), close, market cap. It gives a genuine daily point-in-time NSE market cap (and shares outstanding), with no dependence on the 06 Oct 2026 snapshot. Parsed with `insiders_clean/market_cap.py`; on the two real files: 3,212 and 2,516 rows, 0 unreadable dates, 0 missing issue sizes, 31 and 12 rows where market cap differs from issue size x close (reported, kept). File-name case differs between years.
- NOT solved: BSE-only securities have no equivalent shares-outstanding file in the BSE bhavcopy. Their market cap stays an open item (candidates: quarterly shareholding XBRL already collected; BSE's own market-cap feed via the in-page collector). Until then BSE-only names get no point-in-time market cap and are flagged, not imputed from the snapshot.
- The PR zip also holds the daily NSE corporate-action file (`bc`, record/ex dates and a purpose text). It is kept as raw bytes (stored by the backfill) and parsed later as a classifier.
- **Adjustment factors come from the exchanges' own prices for both NSE and BSE** (`insiders_clean/adjust.py`): factor on a session = prev_close / previous session's close, where prev_close is the exchange's own base price for the session. A split, bonus or consolidation shows up as a factor far from 1, on either exchange, with no action feed. This covers BSE-only names, which the NSE action feed cannot. Thresholds (structural > 5%, minor > 0.1%) are config to be tuned on data; a previous print older than 10 days gives `unknown`, never a guessed event. Adjusted prices use only factors dated on or before the signal date (no look-ahead; tested).
- HYPOTHESIS to verify on the loaded data: NSE and BSE prev_close are reset for splits and bonuses but may differ on cash dividends; the two exchanges' factors should agree on structural events for dual-listed ISINs. The coverage report will test both. BSE's own corporate-action API answers 403 from outside a browser (Akamai), so a BSE action feed would need the in-page collector.

## 2026-10-09 Simplification directive (owner)
- Price adjustment stays minimal: only structural base-price resets (splits, bonuses, consolidations) are adjusted, using the exchange's own `prev_close`; cash dividends and minor ex-date moves are never adjusted (`kind='minor'` is reported, not applied). Rights issues and demergers that reset the base price by more than 5% also fall in `structural` because the factor cannot tell them apart without an action feed; this is accepted and counted, not engineered around. Prices are baseline reference, not a high-frequency factor backtest.
- Market cap is an indicative size reference only (micro/small/mid/large buckets from the NSE daily file as of the signal date, NSE-listed names; BSE-only names unbucketed and counted). No further work on shares-outstanding precision, BSE market cap, or point-in-time share-count history; the daily file is already built and costs nothing more.
- Priority returns to insider transactions, promoter buying and bulk/block accumulation patterns. `docs/RESEARCH.md` H4 uses the size buckets, not continuous value/market-cap precision.
